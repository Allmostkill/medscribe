## 1. Что это и чем не является

MedScribe слушает приём, превращает речь в текст на вашем компьютере, а языковая модель собирает из текста **черновик** протокола. Вы проверяете и правите его, затем копируете в свою МИС.

- Это **не медицинское изделие**. Оно не ставит диагнозы и не назначает лечение. Модель может ошибиться, выдумать факт или пропустить важное. Каждый протокол читает и исправляет врач и отвечает за него сам. Прочитайте [DISCLAIMER.md](../DISCLAIMER.md) до работы с реальными пациентами.
- Программа рассчитана на **одного врача**: второй аккаунт создать нельзя.

**Куда уходят данные**

| Что | Где находится |
|---|---|
| Учётная запись, сохранённые протоколы | В базе на вашем компьютере (черновики хранятся в зашифрованном виде) |
| Звук приёма и распознавание речи | На вашем компьютере, третьим лицам не передаётся |
| Текст приёма (после частичного обезличивания) | **Уходит в языковую модель, которую вы выбрали** |
| Вкладка «Клинреки» (если не скачана локальная копия рекомендаций) | В рубрикатор Минздрава уходит только код МКБ-10, без данных пациента |

Обезличивание неполное: адреса, места работы, редкие имена и другие сведения могут остаться в тексте. Если вы в России и выбрали зарубежную модель (DeepSeek, OpenAI, OpenRouter и т. п.), это **трансграничная передача данных о здоровье** (152-ФЗ): нужны согласие пациента и уведомление Роскомнадзора. Чтобы текст не покидал компьютер, используйте локальную Ollama и **не выбирайте в ней модели с пометкой cloud**: они работают на серверах Ollama, и текст уходит туда (раздел 4). Для облачной модели программа сама просит поставить галочку «Я понимаю, что текст приёма уйдёт провайдеру». Подробнее: [README, раздел «С кем разговаривает ваш инстанс»](../README.md#с-кем-разговаривает-ваш-инстанс).

## 2. Что понадобится

| Что | Требование |
|---|---|
| Компьютер | Не меньше 16 ГБ оперативной памяти (Docker нужно отдать не меньше 8 ГБ, ещё нужна память для системы и браузера), 4 процессорных ядра, не меньше 15 ГБ свободного места (программа около 5 ГБ, модель речи 5,6 ГБ, запас). Видеокарта не нужна. Проверено на Mac с чипом Apple (Apple Silicon) и на Linux. **Windows 10 и 11 поддерживаются, но установщик для Windows новый: если что-то пошло не так, сообщите автору** |
| Docker Desktop | Программа, в которой «живёт» MedScribe. Нужен Docker Compose версии 2.24 или новее (установщик проверит сам) |
| Языковая модель | Ключ облачного сервиса **или** установленная на компьютере Ollama. Подключается в самой программе уже после установки (раздел 4) |
| Интернет | Для установки (загрузка около 1,2 ГБ) и для скачивания модели речи (около 5,6 ГБ). Облачной языковой модели нужен интернет и во время приёмов |

**Как поставить Docker Desktop**

- macOS: [docs.docker.com/desktop/setup/install/mac-install](https://docs.docker.com/desktop/setup/install/mac-install/)
- Windows: [docs.docker.com/desktop/setup/install/windows-install](https://docs.docker.com/desktop/setup/install/windows-install/)
- Linux: [docs.docker.com/desktop/setup/install/linux](https://docs.docker.com/desktop/setup/install/linux/) (либо Docker Engine: [docs.docker.com/engine/install](https://docs.docker.com/engine/install/))

После установки запустите Docker Desktop (при первом запуске примите условия) и дождитесь, когда он напишет, что работает. **Что вы должны увидеть:** на Mac значок кита в строке меню вверху, на Windows значок кита в трее справа внизу; в окне Docker Desktop внизу слева зелёная пометка «Engine running».

**Память для Docker.** Установщик сам проверяет, что Docker получил не меньше 8 ГБ, и, если нет, остановится и подскажет, что делать. Вручную это так: в Docker Desktop откройте Settings (Настройки), раздел Resources (Ресурсы), поле Memory (Память), поставьте не меньше 8 ГБ и нажмите Apply (Применить). На Windows с WSL 2 память задаётся файлом: создайте в вашей домашней папке (`C:\Users\ВАШЕ_ИМЯ`) файл `.wslconfig` с двумя строками `[wsl2]` и `memory=8GB`, затем в PowerShell выполните `wsl --shutdown` и снова запустите Docker Desktop.

> Команды ниже выполняются в **терминале**. Mac: программа «Терминал» (найдите её через поиск Spotlight: Cmd+Пробел, слово «Терминал»). Windows: PowerShell (Пуск, начните печатать «PowerShell», откройте «Windows PowerShell»; права администратора не нужны). Linux: любой терминал. Вставить скопированную строку: на Mac Cmd+V, в PowerShell правая кнопка мыши (или Ctrl+V), в терминале Linux Ctrl+Shift+V. Выполнить: Enter.

## 3. Установка и первый запуск

Вся установка делается **одной строкой**. Она сама проверяет компьютер, скачивает готовую программу (собирать ничего не нужно), запускает её и открывает браузер.

### 3.1. Быстрая установка: macOS и Linux

1. Убедитесь, что Docker Desktop запущен (раздел 2). Если он не запущен, на Mac установщик попробует запустить его сам и подождёт до 3 минут.
2. Откройте «Терминал», вставьте строку и нажмите Enter:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/Allmostkill/medscribe/main/scripts/install.sh | sh
   ```

3. Дальше установщик работает сам. Вот что вы увидите в терминале:

   | Что написано в терминале | Что происходит |
   |---|---|
   | «Шаг 1 из 6. Проверяю компьютер и Docker» и строки «Компьютер подходит…», «Docker работает.» | Проверка. Если чего-то не хватает, установщик скажет, чего именно и что сделать (раздел 9) |
   | «Шаг 2 из 6. Готовлю папку и скачиваю пакет», «Контрольная сумма совпала.» | Скачивается небольшой пакет с файлами программы и проверяется, что он не повреждён |
   | «Шаг 3 из 6. Устанавливаю файлы», «Файлы установлены в …/medscribe» | Файлы кладутся в папку `medscribe` в вашей домашней папке |
   | «Шаг 4 из 6. Скачиваю образы программы» | Самый долгий шаг: загрузка около 1,2 ГБ, можно пока выпить чаю |
   | «Шаг 5 из 6. Запускаю программу», «База данных готова.» | Программа стартует, ждём базу данных (до 5 минут) |
   | «Шаг 6 из 6. Открываю MedScribe» и строка «Откройте MedScribe: http://localhost:3000/setup#token=…» | **Браузер открывается сам** со страницей создания аккаунта |

4. После этого в терминале идёт строка прогресса, например: «Загружаю модель распознавания речи: 2,3 из ~5,6 ГБ (41 %), осталось ~12 мин». Это докачивается модель речи (подробнее в разделе 4.1). **Пока она качается, вы уже можете создать аккаунт и подключить языковую модель** (разделы 4 и 5); записывать приём можно, когда в терминале появится «Модель распознавания речи готова. Можно записывать приём.» До этого момента в программе показана жёлтая плашка о том, что модель речи ещё загружается.
5. В конце установщик пишет «Готово. Дальше:» и напоминает: подключить языковую модель (Профиль → Настройки ИИ), включить автозапуск Docker Desktop (Settings → General → Start Docker Desktop when you sign in), как обновляться.

Нажатие Ctrl+C во время показа прогресса **безопасно**: установка и загрузка модели идут в фоне, остановится только показ строки прогресса.

**Как открывать программу потом.** Установщик создаёт ярлык **«MedScribe»**.

- **Mac:** ярлык лежит в папке «Программы» (в конце установки Finder сам его покажет). Его видно в Launchpad и через поиск Spotlight (Cmd+Пробел, наберите MedScribe). Перетащите его в Dock, чтобы открывать в один щелчок. Если Docker Desktop выключен, ярлык сам его запустит.
- **Windows:** ярлык «MedScribe» лежит на рабочем столе. Если Docker Desktop выключен, ярлык сам его запустит. Если по двойному щелчку ничего не происходит (например, сетевая политика клиники блокирует скрипты), откройте программу вручную: введите в браузере `http://localhost:3000`.
- **Linux:** ярлык «MedScribe» в меню приложений (и на рабочем столе, если у вас есть такая папка). Docker он **не запускает**: если Docker выключен, окно подскажет команду.

Двойной щелчок поднимает программу (от нескольких секунд до 2–3 минут) и открывает её в браузере. Если не открывается, прочитайте сообщение в окне: оно скажет, что делать (например, «Docker не установлен» или «Docker не запустился за 3 минуты» — откройте Docker Desktop вручную, дождитесь зелёного значка и откройте ярлык снова). Ярлыка нет, если установка шла с `MEDSCRIBE_NO_SHORTCUT=1` или на сервере; тогда открывайте `http://localhost:3000`. Скрипт `scripts/update.sh` (Mac, Linux) ярлык только обновляет: если вы его удалили, он не вернётся. Строка установки (в Windows обновление делается ею) создаёт ярлык заново.

Если браузер не открылся сам (бывает на Linux без графической оболочки), скопируйте ссылку из строки «Откройте MedScribe: …» и вставьте её в адресную строку браузера.

### 3.2. Быстрая установка: Windows

> **Установщик для Windows новый.** Он поддерживается официально, но его проверили на меньшем числе компьютеров, чем для Mac и Linux. Если что-то пошло не так, сообщите автору: сохраните текст из окна PowerShell, он покажет, на каком шаге остановилась установка.

Нужны Windows 10 или 11 (64-разрядная) и Docker Desktop в режиме **Linux-контейнеров** (так по умолчанию; если у вас иначе, установщик скажет, как переключить: правый клик по значку кита, «Switch to Linux containers»).

1. Убедитесь, что Docker Desktop запущен (раздел 2).
2. Откройте PowerShell, вставьте строку **целиком** (это одна строка) и нажмите Enter:

   ```powershell
   [Net.ServicePointManager]::SecurityProtocol='Tls12'; iex ((irm https://raw.githubusercontent.com/Allmostkill/medscribe/main/scripts/install.ps1).TrimStart([char]0xFEFF))
   ```

3. Что вы увидите (шаги окрашены в голубой, успехи в зелёный):

   | Что написано в окне | Что происходит |
   |---|---|
   | «Шаг 1 из 6. Проверяю компьютер и Docker» и зелёные «Готово: …» | Проверка Windows, Docker, версии Compose и памяти |
   | «Шаг 2 из 6. Готовлю папку и скачиваю пакет программы», «Готово: пакет скачан, контрольная сумма совпала» | Небольшой пакет с файлами программы |
   | «Шаг 3 из 6. Копия данных перед обновлением» | При первой установке: «Копия не нужна: это новая установка» |
   | «Шаг 4 из 6. Устанавливаю файлы и запускаю программу», «Скачиваю программу (около 1,2 ГБ, можно пока выпить чаю)…» | Самый долгий шаг. Файлы лежат в папке `medscribe` в `C:\Users\ВАШЕ_ИМЯ` |
   | «Шаг 5 из 6. Жду готовности и открываю MedScribe», зелёная ссылка | **Браузер открывается сам** со страницей создания аккаунта |
   | «Шаг 6 из 6. Модель распознавания речи» | Показ прогресса загрузки модели речи (раздел 4.1) |

4. В конце: «MedScribe установлен.», сообщение о ярлыке «MedScribe» (им открывают программу каждый день) и подсказки: подключить языковую модель (Профиль, затем Настройки ИИ), включить автозапуск Docker Desktop.

Ctrl+C останавливает только показ прогресса, установка идёт в фоне. Окно PowerShell можно закрыть, загрузка продолжится.

### 3.3. Если закрыли терминал или что-то пошло не так

**Запустите ту же строку установки ещё раз.** Это безопасно: ваши данные не удаляются, уже скачанное не скачивается заново, а установщик заново покажет прогресс модели и ссылку для входа. То же верно, если установка остановилась на ошибке: прочитайте сообщение (оно написано по-русски и говорит, что сделать), исправьте причину и запустите строку снова. Типичные причины и их решение — в разделе 9.

Если нужен нестандартный порт (3000 занят) или другая папка, добавьте переменную перед строкой установки:

- macOS и Linux: `curl -fsSL https://raw.githubusercontent.com/Allmostkill/medscribe/main/scripts/install.sh | APP_PORT=3100 sh` (папка: `MEDSCRIBE_DIR=/путь/к/папке` на том же месте).
- Windows: сначала выполните `$env:APP_PORT='3100'`, затем строку установки.

### 3.4. Установка на сервер с доменом и HTTPS

Это нужно, если вы хотите открывать MedScribe не на одном компьютере, а с разных устройств по адресу вида `https://med.example.com` (браузер разрешает микрофон только на `localhost` или по HTTPS). **Это проще, чем настраивать всё вручную, но всё ещё для уверенного пользователя:** нужен свой сервер и понимание, что такое домен и DNS. Если сомневаетесь, лучше установить на свой компьютер (3.1 или 3.2), а сервер оставить техническому специалисту.

Что нужно заранее:

- сервер с Linux и установленным Docker (Docker Engine);
- **домен** (например, `med.example.com`) и **запись A** у регистратора домена, указывающая на IP-адрес сервера. Без неё сертификат не выдадут;
- **свободные порты 80 и 443** на сервере (если на нём уже работает nginx или apache, скрипт скажет об этом и остановится, ничего не меняя) и открытые для интернета: если на сервере включён файрвол, откройте их, например `sudo ufw allow 80/tcp && sudo ufw allow 443/tcp` (скрипт файрвол не трогает, только подсказывает);
- адрес почты (на неё Let's Encrypt присылает напоминания о сертификате).

Команда (выполняется на сервере):

```bash
curl -fsSL https://raw.githubusercontent.com/Allmostkill/medscribe/main/scripts/install-server.sh | sh
```

Скрипт задаст два вопроса:

1. «Домен сайта (например med.example.com):» напишите домен латиницей. Для домена в зоне .рф нужна запись в виде `xn--...`, её показывает регистратор.
2. «Почта для сертификата…»: напишите адрес почты.

Ответы можно передать заранее: `MEDSCRIBE_DOMAIN=med.example.com ACME_EMAIL=name@example.com` перед `sh` в конце команды (`... | MEDSCRIBE_DOMAIN=... ACME_EMAIL=... sh`).

Дальше скрипт по порядку: проверяет, что домен уже указывает на сервер и порты свободны; запускает основной установщик (он поставит программу вместе с Caddy: тот сам получает сертификат; загрузку модели речи на этом шаге он не ждёт); ждёт, пока сайт откроется по HTTPS (до 2 минут); печатает ссылку первого входа вида `https://med.example.com/setup#token=…` и совет про файрвол; **и только после этого** показывает строку прогресса загрузки модели речи (раздел 4.1). **Что вы должны увидеть:** «Сайт отвечает: https://…», ссылку и затем строку «Загружаю модель распознавания речи…». Откройте ссылку, создайте аккаунт (раздел 5): это можно делать, пока модель ещё качается. Ссылка с кодом работает до создания аккаунта, никому её не передавайте. Нажатие Ctrl+C во время показа прогресса безопасно: ссылка и советы уже напечатаны, а загрузка модели идёт в фоне.

Если сайт не открылся по HTTPS, скрипт назовёт три частые причины: запись A ещё не указывает на сервер (DNS обновляется до нескольких часов), порты 80 и 443 закрыты файрволом, сертификат ещё выдаётся. Программа при этом запущена: исправьте причину и запустите ту же команду ещё раз. Обновление на сервере: `~/medscribe/scripts/update.sh`.

### 3.5. Ручная установка: запасной путь

Нужна, если вы разработчик или если `raw.githubusercontent.com` у вас не открывается. Всё делается в терминале.

**Шаг 1. Скачайте программу.** Выберите один способ.

- Способ А (если на компьютере есть git):

  ```bash
  git clone https://github.com/Allmostkill/medscribe
  ```

  ```bash
  cd medscribe
  ```

- Способ Б (без git): откройте <https://github.com/Allmostkill/medscribe>, нажмите зелёную кнопку **Code**, затем **Download ZIP**. Распакуйте архив. Откройте терминал в распакованной папке (в ней лежит файл `docker-compose.yml`). Проще всего: напишите в терминале `cd `, перетащите папку в окно терминала и нажмите Enter.

**Что вы должны увидеть:** в терминале вы находитесь в папке с программой (команда `ls` на Mac и Linux или `dir` в Windows показывает файл `docker-compose.yml`).

**Шаг 2. Запустите.**

```bash
docker compose up -d
```

Docker скачает готовые образы (загрузка около 1,2 ГБ) и запустит программу. Когда команда завершилась, терминал можно закрыть: программа продолжит работать сама. **Что вы должны увидеть:** команда завершилась без красных сообщений об ошибке и вернула вас к строке ввода.

**Шаг 3. Дождитесь, пока модель речи скачается** (15–20 минут, раздел 4.1) и **войдите в программу** (раздел 5: ссылку с кодом здесь нужно взять из журнала командой).

В папке, скачанной ZIP-архивом, обновления автоматически не работают: см. раздел 8.

## 4. Модели: распознавание речи и языковая модель

В MedScribe работают две разные модели. Не путайте их.

| | Модель распознавания речи (T-one) | Языковая модель (LLM) |
|---|---|---|
| Что делает | Превращает голос в текст | Собирает протокол, даёт подсказки, проверяет назначения |
| Где работает | На вашем компьютере | Облако **или** ваш компьютер (Ollama) |
| Откуда берётся | Скачивается сама при установке | Вы подключаете её сами в программе |
| Нужен ли ключ | Нет | Для облака да |

### 4.1. Модель распознавания речи (T-one)

- Скачивается **сама**, в фоне, сразу после запуска программы: около 5,6 ГБ с сайта HuggingFace, обычно 15–20 минут.
- **Прогресс показывает установщик** в терминале, например: «Загружаю модель распознавания речи: 2,3 из ~5,6 ГБ (41 %), осталось ~12 мин». Когда всё готово, он пишет «Модель распознавания речи готова. Можно записывать приём.» В самой программе пока модель не готова, вверху стартового экрана стоит жёлтая плашка «Модель распознавания речи ещё загружается…»; она сама исчезнет.
- Браузер открывается и аккаунт можно создать до того, как модель докачалась. Но **записывать приём нельзя**, пока модель не загрузилась.
- Хранится в отдельном хранилище Docker (оно называется `tone-models`) и **повторно не скачивается**, даже если вы остановите и снова запустите программу или обновите её.
- Во время работы занимает около 5 ГБ памяти.

Если окно с прогрессом закрыли, ничего страшного: загрузка идёт в фоне. Чтобы снова увидеть прогресс, запустите ту же строку установки ещё раз (раздел 3.3). Или посмотрите журнал распознавания в папке программы:

```bash
docker compose logs -f tone
```

Выйти из просмотра: нажмите Ctrl+C (программа при этом не остановится).

**Как понять, что модель готова.** Откройте в браузере адрес <http://localhost:3000/api/health> (на Mac и Linux можно и командой `curl http://localhost:3000/api/health`). Ответ выглядит так:

```
{"status":"ok","llm":false,"tone":true,"db":true,"uptimeSec":120}
```

Нужное для распознавания поле: **`tone`**. `true` значит, что модель речи загружена и отвечает. `false` значит, что она ещё качается или не запустилась.

**Если HuggingFace медленный или недоступен.** Если загрузка не двигается 10 минут, установщик сам напишет об этом. Можно скачать модель через зеркало. Откройте файл `.env` в папке программы (создайте его, если нет: в папке установщика он обычно уже есть, а при ручной установке сначала `cp .env.example .env`), добавьте строку с адресом зеркала и примените:

```env
HF_ENDPOINT="https://hf-mirror.com"   # или адрес вашего зеркала
```

```bash
docker compose up -d
```

Работу конкретного зеркала с T-one авторы не проверяли. О том, как открыть файл `.env`, см. раздел 4.5.

**Точнее: GigaAM v3 (по желанию).** Рядом с T-one есть второй движок распознавания, GigaAM v3 (Сбер). Его стоит включить, если собеседник сидит далеко от микрофона или в комнате шумно: итоговая расшифровка тогда получается точнее.

- Живой текст во время приёма по-прежнему пишет T-one. GigaAM работает, когда вы нажимаете **«Завершить»** (или **«Завершить и расшифровать»** в режиме стенографа), а также по кнопке **«Расшифровать»** на стартовом экране.
- Модель скачивается один раз, около 230 МБ, и только по вашей команде. После этого работает без интернета. Нужно около 300 МБ свободного места на диске. Памяти понадобится немного больше.
- Звук не покидает компьютер: обе модели работают здесь.
- Включение и возврат на T-one — в разделе 7, карточка «Распознавание речи». Если загрузка с HuggingFace не удалась, при недоступном сайте используется тот же адрес зеркала из `.env`, что и выше.

### 4.2. Языковая модель: что выбрать

Подключается **в самой программе**, после установки: «Профиль» → вкладка «Настройки ИИ» → карточка «Языковая модель». Выберите вариант.

| | Облачная модель | Локальная модель (Ollama) |
|---|---|---|
| Примеры | DeepSeek, OpenAI, OpenRouter | Ollama на вашем компьютере |
| Куда уходит текст приёма | К провайдеру (для России: трансграничная передача, см. раздел 1) | Остаётся на компьютере (если модель не облачная: модели с пометкой cloud работают на серверах Ollama) |
| Скорость | Быстро | Медленнее |
| Что нужно | Ключ провайдера (обычно платный) и интернет | Мощный компьютер: 24–32 ГБ памяти и больше (раздел 4.4) |
| Сложность | Проще | Сложнее |

**Где взять ключ облачного провайдера**

- DeepSeek: [platform.deepseek.com/api_keys](https://platform.deepseek.com/api_keys)
- OpenAI: [platform.openai.com/api-keys](https://platform.openai.com/api-keys)
- OpenRouter: [openrouter.ai/keys](https://openrouter.ai/keys)

Ключ — это длинная строка символов. Относитесь к ней как к паролю: никому не показывайте. Программа хранит его в базе зашифрованным и обратно не показывает (видны только последние четыре символа).

Быстрый путь к карточке: на стартовом экране нажмите **«Подключить»** в жёлтой плашке «Языковая модель не подключена…». Она открывает нужную вкладку.

### 4.3. Подключение облачной модели

1. Войдите в программу, нажмите **«Профиль»**, откройте вкладку **«Настройки ИИ»**. Найдите карточку **«Языковая модель»**.
2. Выберите плитку **«Облачная модель»** («Адрес API и ключ от провайдера»). Над полями появится жёлтое предупреждение. Прочитайте его: текст приёма после частичного обезличивания будет отправляться этому провайдеру, и, если его серверы за рубежом, это трансграничная передача данных о здоровье (152-ФЗ). Нужны письменное согласие пациента и уведомление Роскомнадзора. Обезличивание неполное.
3. Заполните поля (для примера):

   | Провайдер | Адрес API | Модель |
   |---|---|---|
   | DeepSeek | `https://api.deepseek.com` | `deepseek-chat` |
   | OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
   | OpenRouter | `https://openrouter.ai/api/v1` | любая из их каталога |

   В поле **«Ключ API»** вставьте ключ провайдера. Адрес пишите без `/chat/completions` на конце (если вставите с ним, программа сама его уберёт).
4. Поставьте галочку **«Я понимаю, что текст приёма уйдёт провайдеру»**. Это обязательно: **пока галочки нет, кнопка «Сохранить» не нажимается**. Та же галочка нужна для моделей Ollama с пометкой cloud и для Ollama по адресу, который не похож на локальный (текст приёма уходит по этому адресу).
5. Введите **свой пароль** от MedScribe в поле «Ваш пароль (для подтверждения)» и нажмите **«Сохранить»**.

   **Что вы должны увидеть:** «Сохранено. Новые протоколы будут составляться этой моделью.» Ключ и пароль из формы после сохранения стираются: так задумано.
6. Нажмите **«Проверить подключение»**. **Что вы должны увидеть:** «Работает, ответ за … мс». Если появилась красная причина, найдите её в таблице раздела 9.

Чтобы поменять ключ, вставьте новый в то же поле (если оставить его пустым, прежний сохраняется, пока адрес остаётся тем же). Чтобы убрать модель, введите свой пароль в поле «Ваш пароль (для подтверждения)», нажмите **«Отключить»** и подтвердите кнопкой **«Да, удалить»** (программа спросит: «Удалить сохранённые настройки и ключ? Вернуть ключ будет нельзя.»). Кнопка «Отмена» оставляет всё как есть.

В блоке **«Дополнительно»** есть переключатель «Режим JSON (отключите, если модель его не поддерживает)» и поле «Ожидание ответа, с» (по умолчанию 60 секунд для облака). Менять их нужно, только если проверка подключения или протокол сообщают о проблеме.

### 4.4. Подключение локальной модели (Ollama)

Текст приёма остаётся на компьютере (если модель не облачная), но нужен мощный компьютер, а протокол собирается дольше.

1. Установите Ollama с сайта [ollama.com](https://ollama.com) и запустите её.
2. Скачайте модель командой, подставив имя модели из каталога [ollama.com/library](https://ollama.com/library). **Не выбирайте модели с пометкой cloud** (в названии `-cloud` или `:cloud`): они работают на серверах Ollama, и текст приёма уйдёт туда:

   ```bash
   ollama pull имя-модели
   ```

3. Задайте для Ollama длину контекста **16384 или больше** (иначе длинную стенограмму она «забудет» с начала). Для долгих приёмов (20–30 минут) может понадобиться 32768, но тогда модели нужно ещё больше памяти. Это настройка самой Ollama, не MedScribe:
   - macOS (приложение Ollama): выполните в терминале `launchctl setenv OLLAMA_CONTEXT_LENGTH 16384`, затем закройте и снова запустите Ollama. Эта настройка **пропадает после перезагрузки Mac**: повторяйте команду после каждой перезагрузки. Если в настройках приложения Ollama есть пункт про длину контекста, можно выставить её там (есть ли он в вашей версии, проверьте сами).
   - Windows и Linux: задайте переменную окружения `OLLAMA_CONTEXT_LENGTH` со значением `16384` и перезапустите Ollama. Точные шаги для вашей системы смотрите в документации Ollama: [docs.ollama.com/faq](https://docs.ollama.com/faq).
4. В MedScribe откройте **«Профиль»** → **«Настройки ИИ»** → карточка **«Языковая модель»**. Плитка **«Ollama на этом компьютере»** выбрана сразу, и программа сама ищет Ollama. **Что вы должны увидеть:** «Ollama найдена, моделей: N» (зелёным).
5. В списке **«Модель»** выберите скачанную модель (рядом написаны размер и число параметров). Если у модели пометка «cloud», появится предупреждение, а для сохранения понадобится галочка «Я понимаю, что текст приёма уйдёт провайдеру»: для локальной работы выберите другую модель.
6. Введите **свой пароль** от MedScribe в поле «Ваш пароль (для подтверждения)» и нажмите **«Сохранить»**. **Что вы должны увидеть:** «Сохранено. Новые протоколы будут составляться этой моделью.»
7. Нажмите **«Проверить подключение»**: «Работает, ответ за … мс». Локальная модель отвечает дольше облачной (время ожидания по умолчанию 180 секунд, оно меняется в «Дополнительно»).

**Если Ollama не нашлась.** Вместо зелёной строки будет жёлтая подсказка «Ollama не найдена. Запустите её…». Проверьте, что Ollama запущена, и нажмите **«Найти ещё раз»**. Если не помогло, поля «Адрес Ollama» и «Модель» можно заполнить вручную: адрес обычно `http://host.docker.internal:11434/v1`, модель, например, `qwen2.5:7b` (пример названия; проверьте своё командой `ollama list`).

**Какую модель выбрать.** На нашем стенде проверены `qwen2.5:7b` (лёгкая, около 4,7 ГБ, работает, но иногда путает, кто говорит) и T-lite (`hf.co/t-tech/T-lite-it-2.1-GGUF:Q8_0`, хорошо по-русски, около 8,7 ГБ). Ответили на проверку подключения также `qwen3-vl:8b`, `gemma3:4b` и `deepseek-r1:7b`. Начните с `qwen2.5:7b`; если памяти хватает, попробуйте T-lite. Качество на настоящих приёмах мы не гарантируем: проверяйте каждый протокол. Более крупные модели, как правило, ошибаются реже, но им нужно больше памяти. Ориентировочно (числа приблизительные, зависят от модели): модель на 14 млрд параметров занимает около 9 ГБ памяти, ещё около 3 ГБ уходит на «память разговора» при длине контекста 16384, и около 8 ГБ нужно самому MedScribe. В сумме получается примерно 20 ГБ и больше, поэтому для такой связки нужен компьютер с 24–32 ГБ памяти; на 16 ГБ она не поместится. Пример семейства моделей для знакомства: Qwen (пример, проверьте актуальные названия и размеры в каталоге ollama.com/library).

> **Linux.** Ollama по умолчанию слушает только сам компьютер, и программа из Docker может её не увидеть (карточка скажет «Ollama не найдена»). Основной способ: задайте для Ollama переменную `OLLAMA_HOST=172.17.0.1` (это адрес моста `docker0`, на который указывает `host-gateway`; проверьте свой командой `ip addr show docker0`). Способ задать переменную смотрите в документации Ollama. Docker должен быть запущен раньше Ollama, иначе этого адреса ещё не будет. Запасной вариант: `OLLAMA_HOST=0.0.0.0`, но тогда Ollama без пароля станет доступна всей вашей сети, и порт 11434 нужно закрыть файрволом для внешней сети, оставив доступ только подсетям Docker.

### 4.5. Для опытных: языковая модель через файл .env

Тот же результат можно получить без интерфейса, через файл настроек. Пока в кабинете ничего не сохранено, действует `.env`; **сохранённое в кабинете имеет приоритет**, а кнопка «Отключить» (с подтверждением «Да, удалить» и паролем) возвращает `.env`. Откуда взяты настройки, видно по строке состояния: в конце написано «· из файла .env» или «· из личного кабинета». Ключ из `.env` в программе не виден: рядом с ним стоит просто «ключ: задан».

1. В папке программы (у установщика это папка `medscribe` в домашней папке) создайте файл настроек, если его нет:

   ```bash
   cp .env.example .env
   ```

2. Откройте файл `.env` в простом текстовом редакторе (Блокнот; на Mac TextEdit в режиме «простой текст»). Файл начинается с точки, поэтому в Finder он может быть скрыт: нажмите Cmd+Shift+. (точка), чтобы показать скрытые файлы.
3. Найдите строки `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` и впишите значения между кавычками (не добавляйте вторую такую же строку, а замените существующую). Пример для DeepSeek:

   ```env
   LLM_BASE_URL="https://api.deepseek.com"
   LLM_API_KEY="..."
   LLM_MODEL="deepseek-chat"
   ```

   OpenAI:

   ```env
   LLM_BASE_URL="https://api.openai.com/v1"
   LLM_API_KEY="..."
   LLM_MODEL="gpt-4o-mini"
   ```

   OpenRouter (модель выберите из их каталога):

   ```env
   LLM_BASE_URL="https://openrouter.ai/api/v1"
   LLM_API_KEY="..."
   LLM_MODEL="..."
   ```

   Ollama на этом же компьютере:

   ```env
   LLM_BASE_URL="http://host.docker.internal:11434/v1"
   LLM_API_KEY=""
   LLM_MODEL="имя-модели-в-ollama"
   LLM_TIMEOUT_MS="180000"
   # если модель плохо отдаёт JSON:
   # LLM_JSON_MODE="false"
   ```

   Вместо `...` вставьте свой ключ (и имя модели для OpenRouter). `LLM_TIMEOUT_MS` — сколько миллисекунд ждать ответ модели (180000 = 3 минуты).
4. Сохраните файл и примените настройку (в папке программы):

   ```bash
   docker compose up -d
   ```

5. Проверьте: откройте <http://localhost:3000/api/health>, поле **`llm`** должно быть `true` (это значит только, что настройки заполнены; верен ли ключ, покажет «Проверить подключение»).

## 5. Первый вход

Аккаунт создаётся один раз по одноразовому коду, который печатается в журнале программы. Так посторонний, знающий адрес сайта, не сможет создать аккаунт раньше вас. Установщик берёт код из журнала сам и вставляет его в ссылку.

**Шаг 1. Откройте ссылку.** После установки **браузер открывается сам** на странице вида `http://localhost:3000/setup#token=XXXX-XXXX-XXXX-XXXX`. Если это произошло, переходите к шагу 3.

Если браузер не открылся или вы его закрыли, есть два способа:

- Запустите ту же строку установки ещё раз (раздел 3.3): она найдёт код и снова откроет ссылку. Данные не пострадают.
- Или возьмите ссылку из журнала. В терминале перейдите в папку программы (у установщика: `cd ~/medscribe` на Mac и Linux, `cd $env:USERPROFILE\medscribe` в PowerShell) и выполните:

  ```bash
  docker compose logs app | grep -A1 "Код первого запуска"
  ```

  (В Windows PowerShell команды `grep` нет: выполните `docker compose logs app` и найдите в выводе строки «Код первого запуска» и «Откройте».)

  Вы увидите две строки. Во второй есть готовая ссылка вида `http://localhost:3000/setup#token=XXXX-XXXX-XXXX-XXXX`. Если строк нет, подождите минуту и повторите: код печатается, когда база запустилась.

**Шаг 2. Страница создания аккаунта.** Вы увидите страницу «Первый запуск — Создайте учётную запись врача». Если открыть адрес `/setup` без ссылки, в форме появится поле «Код первого запуска»: вставьте туда код `XXXX-XXXX-XXXX-XXXX` из журнала.

**Шаг 3. Заполните форму.**

| Поле | Что писать |
|---|---|
| ФИО | Например, Иванов Иван Иванович |
| Email | Ваш адрес (будет логином для входа) |
| Специальность | Выберите из списка: под неё настраиваются подсказки и чек-листы |
| Пароль (не короче 8 символов) | Придумайте пароль |
| Повторите пароль | Тот же пароль |

Нажмите **«Создать аккаунт»**.

**Что вы должны увидеть:** вы вошли в программу, открылся экран «Начало приёма».

Если вы закрыли программу, то в следующий раз открывайте <http://localhost:3000>, вводите email и пароль и нажимайте **«Войти»**. После нескольких неудачных попыток может появиться картинка с символами: введите их в поле «Код с картинки».

**Второй аккаунт создать нельзя.** Ссылка `/setup` после создания аккаунта ведёт на главную. Код действует до создания аккаунта; если приложение перезапустили раньше, в журнале будет новый код, берите последний.

## 6. Как провести приём

Все названия кнопок ниже совпадают с надписями на экране.

### 6.1. Перед приёмом (по желанию)

- **Настройки** (значок шестерёнки вверху). Откроется окно с двумя переключателями:
  - **«Режим стенографа»**: **только для очного приёма**. Во время приёма идёт только запись, без текста и подсказок; расшифровка и протокол делаются в конце. Для записи звонка («Онлайн-приём») этот режим не применяется.
  - **«Разбор общения после приёма»**: подсказки, где ту же мысль можно было сказать иначе. Появляются в истории приёма, во время приёма не показываются.

  Закройте окно кнопкой **«Готово»**.
- **«Из МИС: предыдущий приём»** (кнопка «Добавить»). Вставьте протокол прошлого визита или выписку, чтобы модель учла анамнез и текущую терапию, а не выдумывала их. Текст нигде не сохраняется и живёт до нажатия «Новый приём»; в модель он уходит после того же частичного обезличивания, что и стенограмма (раздел 1).
- **Тип приёма**: переключатель **«Первичный»** / **«Повторный»** в карточке «Очный приём».
- **Клинические рекомендации** (список вверху): «Международные КР» или «Российские КР (Минздрав)».
- **«Проверить микрофон»** (карточка «Микрофон» на стартовом экране). Нажмите и скажите несколько слов: пока идёт проверка (5 секунд), движется полоса уровня. **Что вы должны увидеть:** «Микрофон вас слышит.» Если звук очень тихий или его нет, появится подсказка проверить выбранный микрофон в системе и в браузере. Если браузер не дал доступ, вы увидите понятную причину (например, «Нет доступа к микрофону…»).
- **Плашка состояния** над этой карточкой. Она появляется, только если что-то не готово: нет связи с программой, не отвечает база, ещё загружается модель речи, не подключена языковая модель. Что делать с каждым сообщением, написано в разделе 9. Когда всё в порядке, плашки нет.

### 6.2. Выберите способ записи

| Карточка | Когда использовать | Кнопка |
|---|---|---|
| **Очный приём** (микрофон) | Пациент рядом с вами | **«Начать приём»** |
| **Онлайн-приём** (на карточке подписано «Zoom / Teams / Meet в браузере») | Приём по видеосвязи в веб-версии Zoom, Teams или Meet, открытой во вкладке Chrome или Edge | **«Записать звонок»** |

**Микрофон.** Браузер спросит разрешение на доступ к микрофону: нажмите «Разрешить». Это работает по адресу `localhost` (для работы с другого компьютера нужен HTTPS, см. раздел 8).

**Онлайн-приём.** Программа записывает **оба голоса сразу**: звук вкладки со звонком (собеседник) и ваш микрофон. Они смешиваются в одну запись, которая и расшифровывается.

1. Откройте звонок в браузере **Chrome или Edge**, в отдельной вкладке (веб-версия Zoom, Teams или Meet).
2. **Лучше в наушниках:** без них собеседник может попасть в запись дважды (его голос из колонок попадёт в ваш микрофон).
3. В MedScribe нажмите «Записать звонок». Браузер покажет окно выбора, чем поделиться.
4. Выберите вкладку со звонком (в Chrome раздел **«Вкладка Chrome»**) и включите галочку звука вкладки (в Chrome: **«Также поделиться звуком вкладки»**). Если звук не выбран, программа сообщит: «Звук вкладки не выбран. Нажмите «Записать звонок» ещё раз, выберите вкладку со звонком и включите «Также поделиться звуком вкладки»».
5. Браузер спросит доступ к микрофону: нажмите «Разрешить».

**Что вы должны увидеть:** на экране приёма начинает появляться стенограмма.

Если во время приёма нажать в браузере «Прекратить показ» (или закрыть вкладку со звонком), появится сообщение: «Показ вкладки остановлен: голос собеседника больше не записывается, пишется только ваш микрофон». Завершите приём или начните запись звонка заново.

Звонок в отдельной программе Zoom или Teams так записать нельзя: Chrome не отдаёт звук окна программы. Safari и Firefox звук вкладки не дают.

### 6.3. Идёт запись

На экране блок **«Стенограмма приёма»**: текст появляется по мере речи. Рядом:

- **«Клинические инсайты»**: подсказки по ходу приёма, кнопка **«Обновить»**;
- **«Фарма-безопасность»**: предупреждения по назначаемым препаратам;
- чек-лист стандарта приёма (на телефоне вкладка **«Стандарт»**): отмечает, что уже обсуждено;
- справочники (вкладки **«МКБ-10»**, **«Клинреки»**, **«Препараты»**, **«Расчёты»**, **«Шаблоны»**).

Под стенограммой есть строка «Дописать реплику врача вручную…»: напечатанная фраза добавляется в стенограмму как реплика врача.

Во время записи программа не знает, кто говорит. После остановки записи она делит реплики по голосам, и каждый голос получает номер. Кто из них врач, решает ИИ: врач и пациент отмечаются как «Врач» и «Пациент», третий человек как «Спикер N». Если ИИ не подключён, вы увидите «Спикер 1» и «Спикер 2». Проверьте метки: программа может ошибиться, а один и тот же человек иногда получает два номера.

**Когда вы остановите запись**, программа в фоне заново расшифровывает приём по полной записи (над стенограммой видно «Уточняем стенограмму по полной записи приёма — текст ниже обновится сам»). Живой текст остаётся на экране, пока уточнённый не готов, и подменяется им сам.

**Режим стенографа (только очный приём).** Вместо живого текста вы увидите таймер и индикатор уровня звука. Запись идёт до 60 минут (длинная делится на сегменты автоматически) и сохраняется в браузере. Для завершения нажмите **«Завершить и расшифровать»**. Дальше два этапа: «Этап 1 из 2: Расшифровка» и «Этап 2 из 2: AI размечает спикеров».

**Если распознавание речи недоступно или оборвалось**

| Что вы видите | Что это значит и что делать |
|---|---|
| «Живая расшифровка прервалась: модель распознавания речи недоступна. Звук приёма продолжает сохраняться в браузере…» | Запись сохранена в браузере примерно каждые 5 секунд: при обрыве обычно теряются лишь последние секунды. Если сохранить звук не удалось (например, нет места), программа сообщит об этом. Продолжайте приём и остановите запись как обычно: программа попробует расшифровать звук целиком. Состояние модели смотрите на стартовом экране (плашка) и в разделе 9 |
| «Расшифровать запись не удалось. Она сохранена в браузере: кнопка «Расшифровать» на стартовом экране (хранится до 7 дней)» | Живого текста не было или он неполный (расшифровка обрывалась), а полная расшифровка не получилась. Звук лежит в **этом же браузере**. Когда модель речи заработает, на стартовом экране нажмите **«Расшифровать»** у найденной записи |
| «Живая расшифровка прерывалась, поэтому звук приёма сохранён в браузере…» | Вы сформировали протокол или начали новый приём, а живая стенограмма была неполной. Протокол собран по тому тексту, что успел появиться. Полный звук сохранён: расшифруйте его на стартовом экране кнопкой **«Расшифровать»** и сверьте с протоколом |
| «Запись приёма сохранена в браузере: кнопка «Расшифровать»…» | Вы перешли к протоколу или новому приёму раньше, чем программа закончила уточнять стенограмму. Звук не потерян: его можно расшифровать на стартовом экране |
| «Полная расшифровка не нашла речи в записи. Звук сохранён в браузере…» | Живая расшифровка была неполной, а полная речи не нашла. Проверьте звук кнопкой **«Расшифровать»** на стартовом экране или удалите его кнопкой **«Удалить»** |
| «Живая расшифровка остановилась: сессия истекла…» | Завершите запись и войдите заново |

**Если во время записи нажать «Профиль» или «Выйти»**, программа спросит, остановить ли запись. Если согласиться, запись остановится, а звук сохранится в браузере и появится на стартовом экране с кнопкой **«Расшифровать»**.

Звук сохраняется примерно каждые 5 секунд, поэтому при закрытии вкладки или сбое обычно теряются лишь последние секунды. Если сохранить звук не удалось (например, нет места в браузере), программа сообщит об этом: тогда в расшифровке будет только сохранённое. Если вкладку закрыли или связь оборвалась, на стартовом экране появится плашка «Найдены незавершённые записи» с кнопками **«Расшифровать»** и **«Удалить»**. В режиме стенографа, если расшифровка не удалась, нажмите **«Повторить расшифровку»**: звук сохранён в браузере. Незавершённые записи старше 7 дней удаляются при открытии программы, поэтому не откладывайте расшифровку.

**Важно для общего компьютера.** Звук незавершённых записей хранится в браузере незашифрованным и не стирается при выходе из программы. Для каждого врача заведите отдельную учётную запись компьютера или отдельный профиль браузера и не оставляйте компьютер без присмотра.

### 6.4. Получите протокол

Нажмите **«Завершить и сформировать протокол»**; запись остановится сама. На телефоне порядок другой: во время записи внизу кнопка **«Завершить запись»**, после неё появляется **«Сформировать протокол»**. Подождите, пока идёт «Анализ и структурирование…».

**Что вы должны увидеть:** страница протокола с полями: «Жалобы пациента», «Анамнез заболевания (Morbi)», «Анамнез жизни (Vitae)», «Аллергологический анамнез», «Данные обследования», «Предварительный диагноз», «Лекарственная терапия», «План лечения / Рекомендации». Внизу пометка «Сохранено в историю» (протокол сохраняется сам).

Вверху предупреждение: **проверьте и отредактируйте данные перед копированием в МИС**. Так и сделайте:

1. Прочитайте каждое поле. Все поля можно править прямо на странице.
   **Ваши правки сохраняются в историю сами**: через пару секунд после того, как вы перестали печатать, внизу экрана (на компьютере) появляется «Сохраняю правки…», затем «Правки сохранены в историю». Если связь пропала, будет надпись «Правки не сохранились — проверьте связь»: проверьте программу (раздел 9) и поправьте любую букву, чтобы сохранение повторилось.
2. Обратите внимание на сверку со стенограммой, которая запускается автоматически:
   - под полем **«Источник в стенограмме»**: цитаты из разговора, на которых оно стоит;
   - метка **«нет опоры в стенограмме»**: в разговоре не нашлось реплики, на которой стоит поле. Для осмотра это часто нормально (врач смотрит молча), а для диагноза, препаратов и доз это повод перечитать;
   - блок **«Прозвучало, но в протокол не попало»** с кнопками **«Добавить в поле»** и **«Скрыть»**;
   - для онлайн-приёма: предупреждение, что в «Данных обследования» есть находки, которые по видео не получить (пальпация, аускультация и подобное);
   - если вы правили протокол после сверки, нажмите **«Сверить заново»**.
3. Нажмите **«Скопировать в МИС»** (или **«Поле»** у отдельного поля) и вставьте текст в свою МИС вручную: программа с МИС напрямую не связана. «Скопировать в МИС» копирует **все восемь разделов** протокола, каждый под своим заголовком; пустые разделы пропускаются. Та же копия есть в личном кабинете, в истории, кнопкой «В МИС» (раздел 7).

### 6.5. Памятка пациенту

Ниже протокола раздел «Памятка пациенту» (простым языком, на руки).

1. Нажмите **«Собрать памятку»**. Она собирается из протокола; сначала проверьте протокол.
2. Прочитайте и поправьте текст. Если появилось «Проверьте числа — их нет в протоколе», сверьте дозировки с протоколом. Для диагнозов некоторых групп текст нужно написать самим.
3. **«Копировать»** или **«Распечатать»**.
4. Если вы потом правили протокол, нажмите **«Пересобрать»** (ваши ручные правки памятки при этом заменятся текстом модели).

Предупреждения о том, когда вызывать скорую или связаться с врачом, подставляются из справочника, а не пишутся моделью.

### 6.6. Следующий пациент

Нажмите **«Новый приём»** вверху. Предыдущий протокол остаётся в истории (раздел 7).

### 6.7. Справочники и настройка рабочего поля

- **Справочники** (блок с вкладками): «МКБ-10» (частые коды, не полная база: точный код проверяйте в официальном классификаторе), «Клинреки» (клинические рекомендации Минздрава), «Препараты» (фарм-справочник), «Расчёты» (клинические калькуляторы и дозы), «Шаблоны» (шаблоны назначений; кнопка **«Заполнить протоколом»** только выбирает шаблон: протокол будет собран по нему, когда вы нажмёте «Завершить и сформировать протокол»; у выбранного шаблона кнопка меняется на «Заполняем этот шаблон», повторное нажатие отменяет выбор).
- Чтобы в «Клинреках» читать полные тексты внутри программы, нужна локальная копия: [README, раздел «Клинические рекомендации: локальная копия»](../README.md#клинические-рекомендации-локальная-копия-необязательно). Без неё вкладка показывает список по коду МКБ-10.
- **Настройка рабочего поля.** На широком экране до начала приёма нажмите **«Настроить рабочее поле»**. Блоки можно двигать и менять размер, убирать с поля кнопкой «Убрать блок с поля». Доступно: **«Добавить виджет»** (**«Чек-лист»** со своими пунктами или **«Заметка»**), **«Сбросить к стандарту»**. Завершите кнопкой **«Сохранить»** (или **«Отмена»**): раскладка запомнится. Заметки из виджета «Заметка» на сервере не сохраняются.

## 7. Личный кабинет

Откройте его кнопкой **«Профиль»** вверху. Вернуться к приёму: **«Назад к приёму»**. В кабинете четыре вкладки.

| Вкладка | Что там |
|---|---|
| **Общие** | «ФИО специалиста» и «Специализация» (можно изменить), email виден, но не меняется. Кнопка «Сохранить» |
| **Настройки ИИ** | Карточка «Языковая модель» (подключение, проверка); «Личный шаблон протокола»; «Распознавание речи»; «Режим работы» (переключатели) |
| **Безопасность** | Двухфакторная защита (2FA) и «Изменить пароль» |
| **История** | «Архив черновиков»: все приёмы, поиск, просмотр, копирование «В МИС» (все восемь разделов протокола, как «Скопировать в МИС» на экране приёма), «Создать протокол» для приёмов без протокола |

**Вкладка «Настройки ИИ»**

- **«Языковая модель»**. Открыв вкладку, вы увидите, подключена ли модель: «Подключена: имя модели · адрес · ключ: …» и в конце «· из личного кабинета» или «· из файла .env». Сам ключ программа не показывает, только последние четыре символа. Если база данных не ответила, вместо этого написано «Не удалось прочитать настройки (база данных недоступна). Повторите через минуту.» и есть кнопка «Обновить». Если модель не подключена, написано «Не подключена — протокола и подсказок не будет. Выберите вариант ниже.» Здесь же модель подключается: плитки «Ollama на этом компьютере» и «Облачная модель», поля, галочка «Я понимаю, что текст приёма уйдёт провайдеру» (обязательна для облачной модели, для моделей Ollama с пометкой cloud и для внешнего адреса Ollama), поле «Ваш пароль (для подтверждения)», кнопки «Сохранить» и «Отключить» (последняя просит подтверждение «Да, удалить» и пароль). Подробно: разделы 4.3 и 4.4. Прямая ссылка на вкладку: <http://localhost:3000/profile?tab=ai>.
- **«Проверить подключение»**. Отправляет модели один короткий запрос без данных пациента. **Что вы должны увидеть:** «Работает, ответ за … мс». Если нет, рядом появится причина и что сделать (тексты ошибок в разделе 9). Если написано, что модель отвечает, но не в нужном формате, откройте «Дополнительно» и отключите «Режим JSON». Если вы вносили правки в форму, но не сохранили, проверяется то, что в форме. Проверку можно запускать не чаще 10 раз за 15 минут.
- **«Личный шаблон протокола»**: напишите свободным текстом, как должен выглядеть ваш протокол (порядок, сокращения). Факты берутся только из разговора. Сохраняется **своей кнопкой «Сохранить»**.
- **«Распознавание речи»**: выбор движка для итоговой расшифровки. Две плитки: **«T-one (Т-Банк) · по умолчанию»** и **«GigaAM v3 (Сбер) · точнее»**. Чтобы включить GigaAM, нажмите её плитку, затем **«Скачать и включить (≈230 МБ)»**. Во время загрузки видно «Загружено … из … МБ», потом «Проверяю контрольные суммы…» и «Запускаю модель…». Когда всё готово, появится «Работает: GigaAM». Чтобы вернуться на T-one, нажмите **«Вернуться к T-one»**. Если загрузка не удалась, будет написана причина и кнопка **«Повторить»**. Пока модель не готова, расшифровка идёт через T-one. Если написано «Служба распознавания речи недоступна», программа не видит службу распознавания: сначала проверьте, что программа запущена.
- **«Режим работы»**: переключатели «Режим стенографа» (только для очного приёма) и «Разбор общения после приёма». **Они сохраняются сразу при переключении**, отдельной кнопки нет. Настройки запоминаются в этом браузере.

Раньше здесь были «Тон ответов» и «Фокус анализа». Их убрали: они ни на что не влияли.

**Выход.** Кнопка **«Выйти из системы»** внизу слева закрывает вашу сессию и на сервере: сохранённый вход («запомнить меня») перестаёт работать.

**Смена пароля.** Вкладка «Безопасность», кнопка «Изменить пароль», введите старый и новый пароль, «Обновить пароль».

**2FA (код из приложения на телефоне).** Необязательна и по умолчанию выключена.

1. Откройте файл `.env` и добавьте или измените строку `ENABLE_2FA=true`.
2. Выполните:

   ```bash
   docker compose up -d
   ```

3. Войдите, откройте «Профиль», вкладку «Безопасность», нажмите **«Включить»**. Появится QR-код: отсканируйте его приложением-аутентификатором (например, Google Authenticator), введите шестизначный код и свой пароль, нажмите **«Подтвердить»**.
4. С этого момента при входе после пароля нужно вводить код 2FA.

**Отключение.** «Профиль», «Безопасность», **«Отключить»**: нужны текущий пароль и код из приложения (не больше 5 попыток за 15 минут). Если вы вернули `ENABLE_2FA` в «выключено», уже включённая защита остаётся, и в кабинете будет только кнопка «Отключить». Включить заново без флага нельзя. Телефон потерян: см. раздел 9.

## 8. Повседневное: остановка, пароль, копия, обновление

> **Где выполнять команды.** Все команды `docker compose …` и `scripts/…` ниже выполняются в **папке программы**. Если вы ставили одной строкой, это папка `medscribe` в домашней папке: на Mac и Linux `cd ~/medscribe`, в Windows PowerShell `cd $env:USERPROFILE\medscribe`. После ручной установки это папка, куда вы скачали программу.

### Остановить и запустить

```bash
docker compose stop
```

```bash
docker compose up -d
```

Ваши данные (аккаунт, протоколы, модель речи) при этом **сохраняются**. После перезагрузки компьютера программа поднимется сама, если вы не останавливали её командой `docker compose stop` (иначе выполните `docker compose up -d`) и в Docker Desktop включён запуск при входе в систему (Settings, General).

> **ОПАСНО.** Команда `docker compose down -v` удаляет **все** данные: базу, секреты и скачанную модель речи (потом снова 5–6 ГБ). Без копии вернуть их нельзя. Обычная команда `docker compose down` данные не трогает.

### Забыли пароль

```bash
docker compose exec app npm run reset-password
```

Команда один раз покажет новый пароль. Старый перестанет подходить. После входа смените пароль в личном кабинете.

### Скрипты копии, восстановления и обновления: где их запускать

Скрипты ниже лежат в папке `scripts` и запускаются **из папки программы** (там, где `docker-compose.yml`). Они написаны для Mac и Linux. **На Windows их нужно выполнять только в WSL (Ubuntu)**: это встроенная в Windows среда, в которой работают команды Linux; в Docker Desktop должна быть включена интеграция с WSL (Settings, Resources, WSL integration). В PowerShell и Git Bash их не используйте: копия ключей получится неверной. Чтобы оказаться в WSL сразу в папке программы, откройте PowerShell в папке программы и наберите `wsl` (или в Ubuntu перейдите в неё командой вида `cd /mnt/c/Users/ВАШЕ_ИМЯ/путь/к/medscribe`).

Если скрипт не запускается с сообщением «Permission denied» (так бывает после скачивания ZIP), запустите его через `bash`, например `bash scripts/backup.sh`.

### Резервная копия

> **Внимание.** Сохранённые протоколы зашифрованы, а ключ шифрования хранится в отдельном хранилище программы (оно называется `secrets`). Без него протоколы прочитать нельзя, и восстановить ключ неоткуда. Поэтому нужна копия **двух** вещей: базы с протоколами и ключей (секретов). Скрипт делает обе. Храните копии отдельно от компьютера, на котором работает MedScribe. Команда `docker compose down -v` удаляет **все** хранилища сразу: базу, ключи и модель речи. Обычные `docker compose down` и `docker compose stop` данные не трогают.

Программа должна быть запущена. Выполните в папке программы:

```bash
scripts/backup.sh
```

Копии попадут в папку `medscribe-backup` в вашей домашней папке. Другую папку можно указать после команды: `scripts/backup.sh ~/другая-папка`.

**Что вы должны увидеть:** строки «Делаю копию базы…», «Делаю копию ключей (секретов)…», затем «Готово. Файлы:» с путями двух файлов: `medscribe-ГГГГ-ММ-ДД_ЧЧММСС.dump` (база) и `medscribe-secrets-ГГГГ-ММ-ДД_ЧЧММСС.tar` (ключи). Скрипт сам проверяет, что оба файла читаются, и не перезаписывает прежние копии. Если что-то пошло не так, он напишет «Копия не сделана, неполные файлы удалены» и причину (чаще всего программа не запущена: проверьте `docker compose ps`).

Файлы закрыты правами (читать их можете только вы): сама папка `medscribe-backup` доступна только владельцу (права 700), файлы копий тоже (600). Это касается и копий, которые установщик делает перед обновлением. В Windows установщик ограничивает доступ к папке `C:\Users\ВАШЕ_ИМЯ\medscribe-backup` только вашей учётной записью; если он написал, что не смог этого сделать, проверьте права папки вручную (Свойства, Безопасность). На Windows папка `medscribe-backup` лежит в домашней папке Ubuntu, а не в `C:\Users\…`: в Проводнике откройте `\\wsl$\Ubuntu\home\ВАШЕ_ИМЯ_В_UBUNTU\medscribe-backup`, чтобы перенести копии на внешний диск. Они содержат чувствительные данные: не публикуйте их и не копируйте в облако без шифрования.

**Важно:** файл ключей (`medscribe-secrets-….tar`) храните **отдельно** от копии базы (`medscribe-….dump`), например на разных флешках, или зашифруйте. Если оба файла лежат в одной папке, любой, кто получит эту папку, сможет прочитать ваши протоколы.

### Восстановление из копии

**Вернуть базу** (вместо ДАТА подставьте часть имени вашего файла):

```bash
scripts/restore.sh ~/medscribe-backup/medscribe-ДАТА.dump
```

Скрипт предупредит, что текущая база (аккаунт, протоколы, черновики) будет **полностью заменена**, и попросит ввести слово `ВОССТАНОВИТЬ`. Любой другой ответ отменяет операцию, ничего не меняя. Если восстановление не удалось, база остаётся прежней. **Что вы должны увидеть:** «База восстановлена». После этого выполните `docker compose up -d`: это применит возможные обновления структуры базы.

**На новом компьютере** порядок такой:

1. Скачайте программу **ручным способом** (раздел 3.5), но **не запускайте** её: быстрая установка запускает программу сразу и создаёт новые ключи, а нужно сначала вернуть старые. Выполните в папке программы команду, которая вернёт ключи:

   ```bash
   scripts/restore.sh --secrets ~/medscribe-backup/medscribe-secrets-ДАТА.tar
   ```

   Скрипт откажется работать, если на компьютере уже есть база MedScribe: новые ключи не подошли бы к ней, и данные стали бы нечитаемыми. **Что вы должны увидеть:** «Ключи восстановлены».
2. Запустите программу:

   ```bash
   docker compose up -d
   ```

3. Подождите минуту, пока запустится база, и верните протоколы командой `scripts/restore.sh` с файлом `.dump` (см. выше).

### Обновление

Данные (аккаунт, протоколы, модель речи, настройки языковой модели) при обновлении **сохраняются**. Файлы `.env` и `docker-compose.override.yml` тоже остаются как есть. Способ зависит от того, как вы ставили.

**Вы ставили одной строкой** (в папке есть скрытый файл `.medscribe-install`). Есть два равнозначных способа:

- Запустите **ту же строку установки** ещё раз (раздел 3.1 или 3.2). Это единственный способ для Windows.
- На Mac и Linux можно запустить скрипт:

  ```bash
  ~/medscribe/scripts/update.sh
  ```

  Он скачивает установщик и запускает его в режиме обновления.

Что делает установщик при обновлении: **если версия программы новая, сначала делает резервную копию** (базу и ключи; на Mac и Linux в папку `medscribe-backup` в домашней папке, в Windows в `C:\Users\ВАШЕ_ИМЯ\medscribe-backup`), затем ставит новые файлы, скачивает новые образы, запускает программу и ждёт её готовности. Если копия не получилась, он останавливается и ничего не меняет. **Что вы должны увидеть:** «Обновление завершено (версия). Состояние:» и три строки (база данных, распознавание речи, языковая модель). Если база «работает», обновление прошло. Распознавание речи после обновления может ещё какое-то время загружаться: это не ошибка. Браузер при обновлении не открывается, откройте <http://localhost:3000> (или ваш `APP_PORT`) сами.

**Вы ставили через `git clone`:**

```bash
scripts/update.sh
```

Скрипт делает по порядку:

1. **Резервную копию** (как `scripts/backup.sh`). Если копия не получилась, обновление останавливается, ничего не меняя.
2. **Загрузку новой версии** (`git pull`).
3. **Скачивание новых образов и запуск** (`docker compose pull`, затем `docker compose up -d`). Если вы разработчик и хотите собрать образы из исходников, запустите `scripts/update.sh --build`.
4. **Ожидание готовности**: до 5 минут проверяет состояние программы и в конце показывает: база данных, распознавание речи, языковая модель.

**Вы скачали ZIP-архив:** скрипт скажет, что такую папку обновить нельзя. Поставьте новую версию быстрой установкой (раздел 3.1 или 3.2) в **новую** папку, а старую можно удалить (в ней **никогда** не выполняйте раздел 10: `down -v` сотрёт все данные). Данные общие, они хранятся в Docker; свой `.env` перенесите в новую папку.

**Если установщик находит данные от `git clone`, ZIP или другой папки** (в Docker уже есть база MedScribe, а у этой папки нет файла `.medscribe-install`), он **сам делает копию** перед тем, как подключить данные к новой версии: запускает из файлов пакета только базу, проверяет, что копия читается, и сохраняет два файла (базу и ключи) в папку `medscribe-backup` в вашей домашней папке (в Windows `C:\Users\ВАШЕ_ИМЯ\medscribe-backup`). Если копия не получилась, он останавливается с понятным текстом и ничего не меняет. Если у вас на сервере свой `Caddyfile` (вы его правили), при обновлении установщик его не заменяет: новая версия кладётся рядом, в файл `Caddyfile.new`, и он напишет об этом; сравните файлы и при желании замените (`mv Caddyfile.new Caddyfile`). Правленый `Caddyfile` установщик не перезаписывает ни на каком этапе (файл заменяется только целиком и только если вы его не правили), поэтому ваши правки не пропадут, даже если установку прервать.

**Структура базы обновляется сама.** При каждом запуске программы (`docker compose up`) специальный сервис `migrate` применяет новые изменения структуры базы, прежде чем запустится само приложение. Данные при этом сохраняются. Если изменение не применилось, приложение не запустится, а это изменение отменяется целиком: смотрите `docker compose logs migrate`.

### Если скрипт не подходит

Те же действия вручную. Команды ниже для Mac и Linux (на Windows только в WSL, см. выше). Копии пишутся вне папки программы и с закрытыми правами.

Копия базы (файл `.dump`):

```bash
mkdir -p ~/medscribe-backup && (umask 077; docker compose exec -T postgres pg_dump -U postgres -d medscribe -Fc > ~/medscribe-backup/medscribe-$(date +%F).dump)
```

Секреты:

```bash
(umask 077; docker compose exec -T app tar -C /app/secrets -cf - . > ~/medscribe-backup/medscribe-secrets-$(date +%F).tar)
```

Восстановление базы из файла копии (вместо ДАТА подставьте дату из имени файла):

```bash
docker compose exec -T postgres pg_restore -U postgres -d medscribe --clean --if-exists < ~/medscribe-backup/medscribe-ДАТА.dump
```

Восстановление секретов на новом компьютере выполните **до** первого `docker compose up`:

```bash
docker compose run --rm --no-deps -T --entrypoint tar init -C /app/secrets -xf - < ~/medscribe-backup/medscribe-secrets-ДАТА.tar
```

Затем `docker compose up -d` и восстановление базы из файла копии.

Обновление вручную (для папки после `git clone`): сначала сделайте резервную копию, затем по очереди:

```bash
git pull
```

```bash
docker compose pull
```

```bash
docker compose up -d
```

Ключ `--build` не нужен: программа запускается из готовых образов. Для папки, поставленной установщиком, обновление вручную не нужно: запустите ту же строку установки (см. выше). Папку из ZIP обновлять вручную нельзя, см. выше.

### Работа с другого компьютера и HTTPS

По умолчанию программа открыта только на самом компьютере (`localhost`). Браузер разрешает микрофон и звук вкладки только на `localhost` или по HTTPS, поэтому по обычному адресу `http://IP-адрес:3000` запись не заработает. Для доступа с другого устройства нужен сервер с доменом и HTTPS: он ставится одной командой, см. раздел 3.4. Если у вас уже есть свой обратный прокси, это задача для технического специалиста: [README, раздел «Доступ с других компьютеров, HTTPS и микрофон»](../README.md#доступ-с-других-компьютеров-https-и-микрофон).

### Журналы

```bash
docker compose logs -f app
```

```bash
docker compose logs -f tone
```

Первая команда показывает журнал программы, вторая — распознавания речи. Выход: Ctrl+C. Журнал обновления структуры базы: `docker compose logs migrate`.

## 9. Если что-то не работает

### Если остановилась установка

Установщик пишет понятные причины по-русски. После исправления причины **запустите ту же строку установки ещё раз**: данные не удаляются, скачанное не скачивается заново.

| Что написано в терминале | Что сделать |
|---|---|
| «Docker не установлен…» / «Docker Desktop не найден» | Установите Docker Desktop (раздел 2), запустите его и повторите строку |
| «Docker не запущен…» / «Docker не запустился за 3 минуты» | Откройте Docker Desktop, примите условия (при первом запуске), дождитесь значка кита и повторите строку |
| «Нет доступа к Docker…» (Linux) | Добавьте себя в группу docker командой, которую показывает установщик, выйдите из системы, войдите снова и повторите |
| «Docker выделено мало памяти…» | Выделите Docker не меньше 8 ГБ (раздел 2) и повторите. Windows: файл `.wslconfig` и `wsl --shutdown`. На Linux-сервере без Docker Desktop сообщение другое («На сервере нужно не меньше 8 ГБ оперативной памяти»): добавьте памяти серверу |
| «Docker Compose … слишком старый» | Обновите Docker Desktop до свежей версии |
| «Docker Desktop работает в режиме Windows-контейнеров» | Правый клик по значку кита в трее, «Switch to Linux containers», повторите |
| «Не удалось скачать пакет» / «Не удалось скачать программу» | Проверьте интернет. Должны открываться `github.com`, `raw.githubusercontent.com` и `ghcr.io`. Повторите строку: скачанное сохранится. Если эти сайты у вас недоступны, используйте ручную установку (раздел 3.5), когда доступ появится |
| «Порт 3000 занят другой программой» | Выберите другой порт (раздел 3.3: переменная `APP_PORT=3100`) и повторите |
| «Здесь ручная установка (git)» или «Папка … не пустая» | В этой папке уже что-то лежит. Укажите другую папку (переменная `MEDSCRIBE_DIR`, раздел 3.3). Данные общие, ничего не удаляйте |
| «Контрольная сумма пакета не совпала» | Файл повредился при скачивании. Повторите строку; если повторяется, не продолжайте и сообщите автору |
| Браузер не открылся сам | Скопируйте ссылку из строки «Откройте MedScribe: …» (в Windows зелёная ссылка) в адресную строку |
| Что-то странное в Windows | Установщик для Windows новый. Сохраните текст из окна PowerShell и сообщите автору |

### Если программа не работает

На стартовом экране над карточками способов записи появляется **жёлтая плашка**, если что-то не готово. Она обновляется сама (раз в 15 секунд, пока есть проблема), поэтому после исправления исчезнет без перезагрузки страницы.

| Что вы видите | Что сделать |
|---|---|
| Плашка «Нет связи с программой…» | Запустите Docker Desktop и выполните `docker compose up -d` в папке программы (раздел 8). Проверьте `docker compose ps` |
| Плашка «База данных не отвечает…» | Подождите минуту (после запуска база стартует не сразу). Если не прошло: `docker compose ps` и `docker compose logs app` |
| Плашка «Модель распознавания речи ещё загружается или не запустилась…» | Сразу после установки это нормально: 15–20 минут, прогресс показывает установщик (если закрыли окно, запустите строку установки ещё раз, раздел 3.3). Если не загружается долго: проверьте интернет и память Docker (строка ниже), при недоступном HuggingFace добавьте зеркало `HF_ENDPOINT` (раздел 4.1) |
| Плашка «Языковая модель не подключена…» | Нажмите ссылку **«Подключить»** в плашке. Она открывает «Профиль», вкладку «Настройки ИИ»; подключите модель по разделу 4.3 или 4.4 |
| Нет ссылки для создания аккаунта | Браузер открывается сам; если нет, запустите строку установки ещё раз или возьмите ссылку из журнала (раздел 5). Если аккаунт уже создан, код не печатается |
| Не уверены, слышит ли программа вас | На стартовом экране нажмите **«Проверить микрофон»** и скажите несколько слов: должна двигаться полоса уровня и появиться «Микрофон вас слышит». Если звук очень тихий или его нет, проверьте, какой микрофон выбран в системе и в браузере (значок замка в адресной строке) |
| Нет доступа к микрофону или звуку вкладки | Браузер даёт его только на `localhost` или по HTTPS: открывайте <http://localhost:3000> именно с этого компьютера. Проверьте, что нажали «Разрешить» в запросе браузера, и что доступ не заблокирован в настройках сайта. Для онлайн-приёма звонок должен быть во вкладке Chrome или Edge, а в окне выбора нужно выбрать вкладку и включить «Также поделиться звуком вкладки» |
| Не уверены, работает ли языковая модель | «Профиль», вкладка «Настройки ИИ», кнопка **«Проверить подключение»**. **Что вы должны увидеть:** «Работает, ответ за … мс». Если нет, рядом будет причина: найдите её в таблицах ниже |
| Ошибка разбора ответа (JSON) | «Профиль» → «Настройки ИИ» → «Дополнительно»: отключите «Режим JSON», нажмите «Сохранить» (нужен пароль) |
| С Ollama протокол не успевает собраться (таймаут) | В «Дополнительно» увеличьте «Ожидание ответа, с» (например, до 300), сохраните. Проверьте, что в Ollama задан `OLLAMA_CONTEXT_LENGTH` 16384 или больше |
| После обновления программа не запускается, `docker compose logs migrate` показывает ошибку | Обновление структуры базы не применилось и отменено целиком, данные не затронуты. Сохраните текст ошибки и сообщите разработчикам; до исправления для папки с git можно вернуться на прежнюю версию: `git checkout` прежнего коммита и `docker compose up -d` |
| Порт 3000 занят другой программой | Задайте другой порт: в `.env` строка `APP_PORT=3100`, затем `docker compose up -d`, и открывайте <http://localhost:3100> |
| Не хватает памяти, программа «падает» или тормозит | Docker Desktop, Settings, Resources, Memory: поставьте не меньше 8 ГБ, Apply. Закройте лишние программы |
| Забыли пароль | Раздел 8, команда `reset-password` |
| Потерян телефон с 2FA | Выполните команду ниже: она задаст новый пароль и выключит двухфакторную защиту |

Потерян телефон с 2FA:

```bash
docker compose exec app npm run reset-password -- --disable-2fa
```

### Тексты ошибок языковой модели

Когда протокол или подсказки не получились по вине модели, на экране (и в «Проверить подключение») показывается одно из этих сообщений. Настройки меняются в «Профиль» → «Настройки ИИ» (для настроек из `.env` — после правки выполните `docker compose up -d`).

| Сообщение начинается так | Что сделать |
|---|---|
| «Языковая модель не подключена…» | Подключите её: «Профиль» → «Настройки ИИ» (раздел 4) |
| «Провайдер языковой модели отклонил ключ…» | Вставьте ключ заново в поле «Ключ API» (нет ли лишних пробелов, не отозван ли ключ) и сохраните |
| «У провайдера языковой модели закончились средства…» | Пополните баланс у провайдера |
| «Провайдер временно ограничил запросы…» | Подождите минуту и повторите; если повторяется, проверьте баланс |
| «Модель не найдена…» | Проверьте название модели и адрес API (адрес без `/chat/completions` на конце) |
| «Провайдер не принял запрос…» | Если модель не поддерживает JSON-режим, отключите «Режим JSON» в «Дополнительно» |
| «Адрес модели не должен содержать логин и пароль…» | Уберите `логин:пароль@` из адреса; ключ вводится в отдельном поле «Ключ API» |
| «Этот адрес нельзя использовать для языковой модели: он указывает на служебный адрес.» (код `blocked_url`) | Программа не пускает на служебные адреса (внутренние службы, метаданные облака). Укажите адрес провайдера из его документации; для Ollama `http://host.docker.internal:11434/v1` |
| «Не удалось прочитать настройки языковой модели из личного кабинета (база данных недоступна). Текст приёма не отправлен…» (код `settings_unavailable`) | Временная неполадка базы: повторите через минуту. Если повторяется, проверьте, что программа здорова: `docker compose ps` и `docker compose logs --tail 50 app`. Текст приёма при этом никуда не уходил |
| «Адрес модели стал указывать в интернет; подтвердите передачу в Профиль → Настройки ИИ.» (код `transfer_unconfirmed`) | Адрес, который раньше вёл на ваш компьютер или в локальную сеть, теперь ведёт в интернет, а передача не подтверждена. Откройте «Профиль» → «Настройки ИИ», проверьте адрес и, если всё так и задумано, подтвердите передачу галочкой и сохраните. Если вы такого не меняли, отключите модель и проверьте адрес у администратора сети |
| «Адрес модели перенаправляет на другой адрес…» (код `redirect`) | Адрес отвечает «перейдите в другое место». Возьмите конечный адрес API из документации провайдера и вставьте его |
| «Сервис языковой модели сейчас недоступен (ошибка на стороне провайдера)…» | Повторите позже |
| «Языковая модель не ответила вовремя…» | Повторите; для локальной модели увеличьте «Ожидание ответа» в «Дополнительно» |
| «Нет связи с сервисом языковой модели…» | Проверьте интернет и адрес; для Ollama проверьте, что она запущена |
| «Модель вернула ответ в неожиданном формате…» | Повторите; если повторяется, отключите «Режим JSON» в «Дополнительно» |

**Ошибки при сохранении настроек в карточке «Языковая модель»** (красный текст под кнопками):

| Сообщение | Что сделать |
|---|---|
| «Подтвердите, что понимаете: текст приёма уйдёт провайдеру» (код `ack_required`) | Поставьте галочку «Я понимаю, что текст приёма уйдёт провайдеру». Она нужна для облачной модели и для моделей Ollama с пометкой cloud. Без неё «Сохранить» не нажимается |
| «Неверный пароль» | В поле «Ваш пароль (для подтверждения)» введите пароль от MedScribe |
| «Некорректный адрес. Нужен адрес вида https://api.example.com/v1 — без логина, пароля, знаков ? и #.» | Исправьте адрес |
| «Адрес без шифрования (http://) допустим только для модели на этом компьютере или в вашей локальной сети. Для интернета используйте https://.» | Для облачного провайдера замените `http://` на `https://` |
| «Этот адрес нельзя использовать для языковой модели: он указывает на служебный адрес.» (код `blocked_url`) | См. таблицу выше |
| «Не удалось найти сервер по этому адресу. Проверьте, как написан адрес.» | Опечатка в адресе или нет интернета |
| «Укажите название модели…» | Впишите название модели |
| «Ключ слишком длинный или содержит пробелы и служебные символы. Скопируйте его заново.» | Скопируйте ключ ещё раз целиком, без пробелов по краям |
| «Проверьте поля: не все настройки модели заполнены правильно.» | Проверьте все поля и поле «Ожидание ответа» (от 5 до 600 секунд) |

Как посмотреть журналы: см. конец раздела 8. Если не помогло, проверьте общее состояние: `docker compose ps`.

## 10. Удаление программы

> **Сначала сделайте резервную копию** (раздел 8), если протоколы вам ещё нужны. Удаление безвозвратно стирает базу, секреты и модель речи.

1. Откройте терминал в папке программы (у установщика это `medscribe` в домашней папке, раздел 8) и выполните:

   ```bash
   docker compose down -v
   ```

   Это остановит и удалит программу вместе со всеми её данными.
2. Удалите папку с программой и ярлык «MedScribe»: на Mac приложение `MedScribe` из папки «Программы», в Windows файл `MedScribe` с рабочего стола, на Linux `medscribe.desktop` (`~/.local/share/applications`) и `MedScribe.desktop` с рабочего стола.
3. Образы программы можно удалить в Docker Desktop (раздел Images), а при желании и сам Docker Desktop обычным способом для вашей системы.
