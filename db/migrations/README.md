# Миграции схемы базы

Базовая схема создаётся один раз при первом запуске на пустой базе из `db/initdb/20-schema.sql`. Всё, что меняет схему позже, оформляется миграцией в этой папке. Сервис `migrate` применяет новые миграции при каждом `docker compose up` до старта приложения.

## Как написать миграцию

- Файл называется `NNNN_описание.sql`: четыре цифры и короткое описание латиницей, например `0001_add_visit_notes.sql`. Порядок применения - по номеру.
- Миграция пишется относительно схемы из `db/initdb/20-schema.sql` и всех предыдущих миграций. Саму `20-schema.sql` не правьте: она выполняется только на пустой базе, а базовая схема считается неизменной.
- Применённые миграции не редактируйте. Нужна правка - новый файл.
- Каждая миграция выполняется в одной транзакции вместе с записью в `public.schema_migrations`: либо применяется целиком, либо никак. Не пишите в файле `begin` и `commit`. Команды, которые нельзя выполнить в транзакции (`create index concurrently`, `alter type ... add value` с использованием значения сразу), в миграции недопустимы.
- Для каждой новой таблицы повторите защиту из `20-schema.sql`: `enable row level security`, `force row level security`, `revoke all ... from anon, authenticated`, а для `service_role` - `grant all` на таблицу и её последовательности. Новые таблицы по умолчанию закрыты от ролей PostgREST `anon` и `authenticated`.
- После успешного применения сервис сам отправляет PostgREST сигнал перечитать схему.
